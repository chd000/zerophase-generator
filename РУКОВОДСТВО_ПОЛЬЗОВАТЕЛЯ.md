# Руководство пользователя: генератор артефактов PowerCenter

Генератор из Excel-описания источников создаёт готовые к импорту артефакты Informatica PowerCenter:

- **XML-маппинги** трёх этапов — SRC (выгрузка из источника), DLT (сравнение инкремента с таргетом), TGT (загрузка в таргет);
- **DDL-скрипты** создания таблиц SRC/DLT/TGT в схеме стейджинга;
- **рабочий поток** (workflow) с ворклетами SRC/DLT/TGT и сервисными сессиями логирования;
- **управляющий поток** (`wf_load_prm_ODS_<СХЕМА>`), запускающий рабочие потоки по списку таблиц.

Рабочие потоки создаются с расписанием ONDEMAND — после импорта они не появляются в IPC Monitor и не требуют ручного снятия с расписания.

## 1. Необходимое ПО

| ПО | Версия | Обязательно | Зачем |
|---|---|---|---|
| Python | 3.9 или новее | Да | интерпретатор |
| Tkinter | входит в Python | Да (для GUI) | графическое окно |
| PyCharm (или другая IDE) | любая | Нет | удобное редактирование настроек |
| Git | любой | Нет | получение обновлений проекта |

Сторонние библиотеки **не требуются** — используются только модули стандартной библиотеки Python. Ничего устанавливать через `pip` не нужно.

### 1.1 Установка Python

**Windows**
1. Скачайте установщик с https://www.python.org/downloads/ (кнопка Latest Python 3).
2. В первом окне установщика отметьте галочку **Add python.exe to PATH**.
3. Нажмите Install Now. Модуль tkinter (Tcl/Tk) входит в стандартную поставку — отдельно ставить не нужно.
4. Проверка: откройте командную строку и выполните `python --version` (должно быть не ниже 3.9).

**macOS** — установщик с python.org (системный Python 3 также подходит).

**Linux** — `sudo apt install python3 python3-tk` (пакет `python3-tk` нужен именно для GUI).

### 1.2 Получение проекта

Скачайте папку проекта любым способом: `git clone https://github.com/chd000/zerophase-generator.git` или архивом (Code → Download ZIP) и распакуйте.

### 1.3 PyCharm (необязательно, но удобно)

1. File → Open → выберите папку проекта.
2. File → Settings → Project → Python Interpreter → Add Interpreter → укажите установленный Python 3.9+.
3. Дожидаться индексации пакетов не нужно — зависимостей нет.
4. Запуск: откройте `main.py` и нажмите зелёную стрелку ▶ (Run). Откроется графическое окно генератора.

Можно и без IDE: `python main.py` из папки проекта, либо двойной клик по `main.py` (на Windows откроется окно + консоль с логами; закрытие консоли закроет генератор).

## 2. Правила работы с Excel-файлом

Входной файл — `.xlsx` с двумя обязательными листами:

- **«Таблицы источника»** — перечень таблиц;
- **«Атрибуты источника»** — перечень полей каждой таблицы.

Названия листов и заголовков должны совпадать буква в букву (регистр не важен). Пример-шаблон: листы уже есть в файлах описания, используемых проектом.

### 2.1 Лист «Таблицы источника»

Заголовки — в **первой строке**, данные — со второй.

| Колонка | Обязательность | Назначение |
|---|---|---|
| СИ | опционально | система-источник (справочно) |
| БД | опционально | база данных (справочно) |
| Схема | **да** | схема-источник, например `ABC_KKT` |
| Таблица источника | **да** | имя таблицы-источника |
| Описание таблиц источников | опционально | описание |
| Инкрементальная таблица | **да** | базовое имя ODS-таблиц, например `ODS_KKT_ABC_TABLE_INC` |
| Таргетная таблица | опционально | имя TGT-таблицы; если пусто — из INC-имени с суффиксом `_TGT` |
| Workflow IPC | опционально | ссылка на поток (справочно) |
| Комментарий | опционально | комментарий |

Строка пропускается, если пусты одновременно «Таблица источника» и «Инкрементальная таблица».

**Из «Инкрементальной таблицы» строятся все имена.** Отрезается суффикс `_INC`, вместо него добавляются `_SRC`, `_DLT`, `_TGT`:

```
ODS_KKT_ABC_TABLE_INC  →  ODS_KKT_ABC_TABLE_SRC
                          ODS_KKT_ABC_TABLE_DLT
                          ODS_KKT_ABC_TABLE_TGT
```

Если колонка пуста, имя строится как `ODS_<Схема>_<Таблица источника>_INC`. Поэтому важно писать в ней имя целиком, включая порядок частей схемы (`KKT_ABC`, а не `ABC_KKT`), если он отличается.

### 2.2 Лист «Атрибуты источника»

Заголовки ищутся в **первых двух строках**, данные — с третьей.

| Колонка | Обязательность | Назначение |
|---|---|---|
| Схема | **да** | связка с листом таблиц |
| Таблица источника | **да** | связка с листом таблиц |
| Атрибут источника | **да** | имя поля; пустые строки пропускаются; если имя заключено в двойные кавычки (`"id"`), кавычки снимаются автоматически |
| Тип данных | **да** | тип из таблицы ниже |
| Описание атрибута | опционально | описание |
| PK | опционально | `Y` — поле входит в первичный ключ |

Таблицы и атрибуты связываются по паре «Схема + Таблица источника» (регистр не важен, пробелы внутри значений удаляются). Атрибуты с парой, которой нет на первом листе, молча пропускаются. Пробелы в начале/конце значений обрезаются автоматически.

### 2.3 Типы данных

| Запись в Excel | Во что превращается |
|---|---|
| `varchar2(100)`, `varchar2(100 char)`, `varchar2(100 byte)` | VARCHAR2(100) |
| `string` | VARCHAR2(1000) |
| `char(1)` | CHAR(1) |
| `number` | NUMBER (порт — double) |
| `number(15)` | NUMBER(15) (порт — decimal) |
| `number(38,20)`, `decimal`, `numeric` | NUMBER(38,20) |
| `long` | NUMBER |
| `date` | DATE |
| `timestamp`, `datetime` | TIMESTAMP(6) |
| `bool`, `boolean` | CHAR(1) |
| `{"type": "...", "logicalType": "timestamp-micros", "precision": ..., "scale": ...}` | Avro/JSON-описание: поддерживаются `timestamp-micros/-millis`, `local-timestamp-*`, `decimal`/`numeric` |

Неподдерживаемый тип не останавливает генерацию: в журнал пишется `[ОШИБКА]`, пропускается только файл соответствующего этапа.

### 2.4 Зарезервированные имена DATE, TYPE, NUMBER, INDEX

Поля с такими именами пишите в Excel как есть — генератор сам разрулит конфликты с зарезервированными словами Oracle:

- в портах XML-маппингов имя заменяется: `DATE→DTE`, `TYPE→TPE`, `NUMBER→NMBR`, `INDEX→INDX`;
- в Sql Query SRC-маппинга поле подставляется в виде `"DATE"`, `"TYPE"`, `"NUMBER"`, `"INDEX"` — двойные кавычки и верхний регистр;
- в DLT/TGT используется уже переименованное (`N.DTE`, `O.TPE` и т.п.).

### 2.5 Первичные ключи (PK)

Поля с `Y` в колонке PK используются в трёх местах: `PARTITION BY` в Sql Query SRC, условие джойна `N/O` в DLT, `DELETE ... IN (...)` в Pre-SQL таргета. Рекомендуется префикс `PK_` — такие поля идут в ключ первыми. Без PK-полей DLT и TGT сгенерировать нельзя (будет ошибка), SRC сгенерируется без PARTITION BY с предупреждением.

## 3. Работа с генератором

### 3.1 Интерфейс

```
┌──────────────────────────────────────────────────────────────────┐
│ Генератор потоков PowerCenter                                    │
├──────────────────────────────────────────────────────────────────┤
│ Файлы                                                            │
│   Файл Excel:      [C:\desc\описание_источников.xlsx] [Обзор…]   │
│   Каталог вывода:  [C:\result]                     [Обзор…]      │
├──────────────────────────────────────────────────────────────────┤
│ Таблицы                                                          │
│ ✓ │ СИ │ БД │ Схема │ Таблица │ Инкрементальная │ SRC-имя │      │
│ ☑ │ …  │ …  │ ABC_KKT│ TABLE  │ ODS_KKT_ABC_…   │ …       │      │
│ ☑ │ …  │ …  │ ZXC_KKT│ TABLE2 │ ODS_ZXC_KKT_…  │ …       │      │
├──────────────────────────────────────────────────────────────────┤
│ [Загрузить таблицы из Excel] [x] Маппинги (XML) [x] DDL-скрипты  │
│ [x] Поток (workflow) [x] Очищать папки схем  [Сгенерировать]     │
├──────────────────────────────────────────────────────────────────┤
│ Журнал:                                                          │
│ Очищено: C:\result\ABC_KKT\xml                                   │
│ Создан: C:\result\ABC_KKT\xml\MAP_ODS_KKT_ABC_TABLE_SRC.XML      │
│ …                                                                │
└──────────────────────────────────────────────────────────────────┘
```

Порядок работы:

1. **Укажите файл Excel** (кнопка «Обзор…» — таблицы загрузятся сразу).
2. **Укажите каталог вывода** — он должен **уже существовать** (создаётся только содержимое: `<каталог>/<Схема>/xml` и `<каталог>/<Схема>/ddl`).
3. **Диалог «Process ID ворклетов»** появляется после загрузки: для каждой таблицы задаются `$$wk_PROCESS_ID` её ворклетов SRC/DLT/TGT. Поля предзаполнены заглушками из настроек — замените реальными значениями или оставьте пустыми (тогда возьмётся значение по умолчанию). Введённые значения запоминаются до закрытия программы.
4. **Отметьте таблицы** кликом по галочке в первой колонке (по умолчанию отмечены все).
5. **Выберите типы генерации:**
   - *Маппинги (XML)* — три маппинга на таблицу;
   - *DDL-скрипты* — один .sql на таблицу (три CREATE TABLE);
   - *Поток (workflow)* — рабочий поток таблицы + управляющий поток схемы;
   - *Очищать папки схем перед генерацией* — включено по умолчанию. Перед записью удаляются папки `xml` и `ddl` **только выбранных схем**: перегенерируя `ABC_KKT`, вы не трогаете лежащую рядом `ZXC_KKT`. Защищённые (read-only) файлы удаляются корректно; если файл заблокирован другой программой, делается три попытки, затем ошибка в журнал.
6. **«Сгенерировать»** — ход и результат видны в журнале внизу.

### 3.2 Структура результата

```
C:\result\
├── ABC_KKT\
│   ├── xml\
│   │   ├── MAP_ODS_KKT_ABC_TABLE_SRC.XML
│   │   ├── MAP_ODS_KKT_ABC_TABLE_DLT.XML
│   │   ├── MAP_ODS_KKT_ABC_TABLE_TGT.XML
│   │   ├── wf_ODS_ABC_KKT_TABLE.XML            ← рабочий поток таблицы
│   │   └── wf_load_prm_ODS_ABC_KKT.XML         ← управляющий поток схемы
│   └── ddl\
│       └── ODS_KKT_ABC_TABLE.sql               ← CREATE TABLE для SRC, DLT, TGT
└── ZXC_KKT\
    └── …
```

Ворклеты внутри рабочего потока называются по той же базе, что и DDL/маппинги: `wk_ODS_KKT_ABC_TABLE_SRC / _DLT / _TGT`. Имя рабочего потока строится от схемы и таблицы источника: `wf_ODS_<Схема>_<Таблица>.XML`.

### 3.3 Генерация из командной строки (без окна)

Удобно для автоматизации и повторных прогонов:

```bat
:: полный набор для всех таблиц файла
python main.py --headless --excel "C:\desc\описание.xlsx" --out "C:\result" --folder MY_FOLDER

:: только две таблицы, без DDL, с очисткой (по умолчанию включена)
python main.py --headless --excel "C:\desc\описание.xlsx" --out "C:\result" --only TABLE1 --only TABLE2 --no-ddl

:: без очистки папок схем
python main.py --headless --excel "C:\desc\описание.xlsx" --out "C:\result" --no-clean
```

| Флаг | Действие |
|---|---|
| `--headless` | работать без графического окна (обязателен для остальных флагов) |
| `--excel`, `--out` | файл описания и каталог вывода |
| `--folder`, `--repository` | имя папки и репозитория PowerCenter в XML (по умолчанию `MY_FOLDER_NAME` / `REPOSITORY`) |
| `--only <таблица>` | генерировать только указанную таблицу (флаг можно повторять) |
| `--no-mappings` / `--no-ddl` / `--no-workflow` / `--no-master` | отключить соответствующий тип генерации |
| `--clean` / `--no-clean` | очищать / не очищать папки схем перед генерацией (по умолчанию очищает) |

Код возврата: `0` — файлы созданы, `1` — ничего не создано (удобно для скриптов CI/регрессии).

> В GUI имя папки и репозитория берутся из настроечного файла; в CLI их можно переопределить флагами.

## 4. Настроечный файл

Все параметры среды собраны в **`generator/settings.py`** — обычный Python-файл, правится в любом редакторе. В GUI эти значения используются как есть, поэтому перед первым запуском замените плейсхолдеры на значения вашей среды.

| Параметр | По умолчанию | Где используется |
|---|---|---|
| `folder_name` | `MY_FOLDER_NAME` | имя папки (FOLDER) в XML |
| `repository_name` | `REPOSITORY` | NAME у REPOSITORY |
| `master_connection` | `IAS_to_GO_Stage` | подключение в сессиях управляющего потока |
| `stage_connection` | `STAGE_CONNECT` | подключение к стейджу (reader/writer DLT/TGT) |
| `source_connection` | `SOURCE_CONNECT` | подключение к БД источника (reader SRC) |
| `integration_service` | `INTEGRATION_SERVICE` | SERVERNAME потока (сервис интеграции) |
| `domain_name` | `DOMAIN` | домен PowerCenter |
| `pmcmd_user`, `pmcmd_password` | `CABS_KIH` | учётка pmcmd в командах управляющего потока |
| `folder_owner` | `Administrator` | OWNER у FOLDER |
| `dbdname` | `OFSDEV` | DBDNAME у SOURCE/TARGET (алиас подключения в маппингах) |
| `owner` | `STAGE` | схема стейджинга: `FROM STAGE.<таблица>`, владелец в DDL |
| `repository_version` / `repository_version_full` | `189` / `189.98` | версия репозитория в XML |
| `codepage` | `UTF-8` | кодировка репозитория |
| `repository_database_type` | `PostgreSQL` | тип БД репозитория |
| `definition_database_type` | `Oracle` | тип БД определений SOURCE/TARGET |
| `ddl_tablespace` | `STAGE_DATA` | TABLESPACE в DDL |
| `audit_log_prefix` | `ODS_CASTA` | префикс имён лог-файлов сервисных сессий |
| `wk_process_id_src` / `_dlt` / `_tgt` | `1000008927/8928/8929` | `$$wk_PROCESS_ID` ворклетов по умолчанию (заглушки) |

Необязательные параметры (заполнять не нужно, если нет особых требований):

| Параметр | Назначение |
|---|---|
| `folder_uuid` | фиксированный UUID папки; по умолчанию новый для каждого файла |
| `creation_date` | фиксированная дата в заголовке XML (`MM/DD/YYYY HH:MI:SS`); по умолчанию текущая |
| `workflow_name`, `workflow_log_name` | переопределение имени рабочего потока и его лога |
| `master_workflow_name`, `master_workflow_log_name`, `master_session_log_name` | переопределение имён управляющего потока и логов |
| `wk_process_id_map` | словарь `{("<ТАБЛИЦА>", "SRC"/"DLT"/"TGT"): id}` — в GUI заполняется автоматически из диалога Process ID |

После правки `settings.py` ничего перезапускать не нужно, если генератор ещё не запущен; если запущен — перезапустите программу.

## 5. Внедрение результатов в PowerCenter

1. Выполните DDL-скрипты на схеме стейджинга (создадутся таблицы SRC/DLT/TGT).
2. Импортируйте маппинги: Workflow Manager → Import → XML (по одному файлу `MAP_*.XML`) либо через `pmrep`.
3. Импортируйте рабочие потоки (`wf_ODS_*.XML`), затем управляющий поток (`wf_load_prm_ODS_<СХЕМА>.XML`).
4. Рабочие потоки имеют расписание ONDEMAND — в IPC Monitor после импорта не отображаются и не требуют снятия с расписания; запуск выполняется управляющим потоком или вручную.

## 6. Частые вопросы

| Симптом | Причина и решение |
|---|---|
| «Укажите файл Excel» / «Укажите каталог вывода» | не заполнены поля вверху окна |
| «Каталог вывода не существует: …» | создайте каталог заранее — генератор создаёт только подпапки схем |
| `[ОШИБКА] Не удалось разобрать тип данных: …` | опечатка в колонке «Тип данных» на листе атрибутов; файл этапа не создан, остальные сгенерированы |
| `[ОШИБКА] Для DLT-маппинга необходимы PK-атрибуты` | на листе атрибутов нет ни одного поля с `Y` в PK |
| В журнале нет «Очищено: …» | выключен чекбокс очистки либо папки схемы ещё не существовало |
| Строки/колонки не подхватились | проверьте точные названия листов («Таблицы источника», «Атрибуты источника») и заголовков; заголовки атрибутов ищутся в первых двух строках |
| Поле DATE/TYPE/NUMBER/INDEX «исчезло» | оно переименовано в DTE/TPE/NMBR/INDX (см. п. 2.4) — это нормальное поведение |
